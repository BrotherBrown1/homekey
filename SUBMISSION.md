## Written problem and solution statement (≤ 500 words)

**The problem.** Every year, billions of dollars of US down-payment-assistance and first-time-homebuyer grant money goes unclaimed. Not because buyers don't qualify — they do — but because they don't know the programs exist. There are roughly 2,500 active programs across federal, state, county, and city governments. They have wildly different eligibility rules (income caps, AMI percentages, profession-specific tracks for teachers, nurses, veterans, first responders), and the rules change quarterly when funding cycles reset. A first-time buyer trying to research this herself faces dozens of poorly-designed government websites, mortgage-broker SEO spam, and outdated lists.

As a Michigan realtor, I hear the same question every week: *"Are there any grants I can use?"* The answer is almost always yes — usually 8 to 15 programs they qualify for, stacking to $30k+ in assistance. But I'm one person, and I can't research grants on top of running showings, doing comparative-market analyses, and managing closings. The people who need this help the most — low-income first-time buyers — get the least of it.

**The solution.** HomeKey is a buyer-facing app powered by two IBM watsonx Orchestrate agents. A buyer answers five quick questions: state, income, household size, profession, first-time-buyer status. The **HomeKey Buyer Advisor** — a conversational watsonx Orchestrate agent — calls our match-grants skill, which combines rule-based filtering (geography, income caps, credit minimums) with watsonx.ai scoring to handle the fuzzy parts (AMI estimates, tag overlap, profession-specific bonuses). The buyer sees their top matches in seconds, each with a per-grant "why you qualify" explanation generated by Granite, plus a direct link to the official application.

But matching is only half the problem. Programs change — funding cycles end, amounts get raised, new programs launch in response to housing-affordability legislation. So we built a second agent: the **HomeKey Curator**. It runs on a weekly schedule. For every program in our database (82 today, growing weekly), it fetches the source URL, hands the live page to watsonx.ai with the stored record, and asks: *Did anything material change?* If the model is confident, the Curator posts a diff to a human-review queue at `/admin`. I approve or reject the change in seconds. The buyer-facing data is always within a week of the source of truth — without a content team.

The buyer flow is free. Buyers who want hands-on help can opt in to a realtor follow-up — converting a public good into a sustainable lead-generation channel for my real-estate practice.

**Impact.** We're shipping at hackathon launch with 82 programs covering all 50 states + DC. Within 90 days, the Curator will have crawled and incorporated changes from every state HFA quarterly funding announcement — something no single human could keep up with. The same architecture (one buyer-facing chat agent + one scheduled curator agent, both powered by watsonx) generalizes to renter assistance, student-loan forgiveness, and small-business grants. HomeKey is the first vertical.

## Written statement on technology (how the project uses watsonx Orchestrate + watsonx.ai)

**watsonx Orchestrate** runs the two agents that make this product work end-to-end:

1. **HomeKey Buyer Advisor** is a conversational agent built in Orchestrate Builder. We imported our REST skills API (`orchestrate/skills-openapi.yaml`) as Orchestrate skills. The agent's system prompt directs it to interview the buyer, then call `matchGrants` once it has enough profile data. If the buyer asks about a specific program, it calls `getGrant`. If the buyer wants a realtor to follow up, it calls `captureLead`. Orchestrate's routing layer decides which skill to invoke and assembles a natural-language response from the JSON results — that's the agentic loop.

2. **HomeKey Curator** is a scheduled agent. It runs once a week, calls our `listGrants` skill to get the work queue, fetches every program's source URL with Orchestrate's HTTP tool, and uses the platform's foundation-model invocation to compare each live page against the stored record. When it detects a real change, it calls `proposeGrantChange` — which writes the diff to a review queue rather than mutating the database. Humans approve or reject. This separation of concerns (autonomous detection + supervised application) is exactly the pattern Orchestrate makes easy.

**watsonx.ai** is the foundation-model brain used in two places:

1. **Inside the Buyer Advisor's `matchGrants` skill:** after a rule-based pre-filter narrows the candidate set, we send the buyer's profile + top candidates to **`ibm/granite-3-8b-instruct`** (configurable via `WATSONX_MODEL_ID`). The model returns a 0–100 score per program plus a one-sentence reasoning. This handles the nuanced ranking that pure rules can't — e.g., a teacher in a HUD revitalization area should rank GNND higher than a generic FHA loan, even though both pass the hard rules. Our `lib/watsonx.ts` wraps the watsonx.ai chat-completions API (with IAM token caching) so we can swap models with one env var.

2. **Inside the Curator's per-grant check:** we hand each live page text + the stored record to watsonx.ai with strict instructions to return JSON describing any material change, conservatively. Granite's structured output is reliable enough to make this fully automated detection — the only human in the loop is the final approval step.

The Orchestrate + watsonx.ai pairing lets one realtor maintain a national grant database that helps thousands of buyers find money they didn't know existed.
